## One bucket per multiset of letters

Given an array of strings, group the anagrams together. `["eat","tea","tan","ate","nat","bat"]` becomes `[["eat","tea","ate"], ["tan","nat"], ["bat"]]`. Order within and across groups does not matter.

The naive approach compares every pair with 02.03 Valid Anagram logic — O(n² · k) for n strings of average length k. At n = 10⁴ and k = 100 that is hundreds of millions of character comparisons. The constraint asks for something closer to O(n · k).

The insight: anagrams are not similar strings — they are **identical keys** under a canonical representation. Hash on that key; all words with the same key land in the same bucket.

## Pick a key: sorted word or count signature

**Sorted key:** copy the word, sort its characters, join — `"eat" → "aet"`. Two anagrams produce the same sorted string. Sorting one word costs O(k log k); n words is O(n · k log k).

**Count signature:** 26 integers for letter frequencies, encoded as a string like `"#1#0#1#0...#1"` or a tuple key. Building it is O(k) per word — O(n · k) total, no log factor. Slightly more code, better asymptotics when k is large.

Both work on the judge. Sorted keys are faster to write in an interview; count keys are the right answer when the interviewer asks you to optimize further.

<Step title="Append the word to map.get(key)">
  First word with a key creates the bucket; later anagrams join it.

  Each bucket is one group; order is unspecified.

## Solution

```ts
function groupAnagrams(strs: string[]): string[][] {
  const groups = new Map<string, string[]>();

  for (const word of strs) {
    const key = [...word].sort().join("");
    if (!groups.has(key)) groups.set(key, []);
    groups.get(key)!.push(word);
  }

  return [...groups.values()];
}
```

Time **O(n · k log k)** — n words, sort each of length k. Space **O(n · k)** for storing every word in a bucket.

With a count signature key instead of sort, time drops to **O(n · k)** and space stays **O(n · k)**.

## In an interview

Restate with the `eat/tea/ate` example. Confirm lowercase, no empty-string edge case required, output grouping only.

Say: "Anagrams share a canonical key; I'll hash on that." Write sorted-key first unless they push on complexity — then switch to count signature without rewriting the whole approach.

Follow-ups: group by k-anagram (same counts within k edits), return groups sorted lexicographically, or stream words one at a time. Bug to mention: using raw word length as key — `"ab"` and `"ba"` have the same length but are not anagrams.
