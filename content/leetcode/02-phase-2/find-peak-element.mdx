## The array is not sorted, but slopes are

A peak element is strictly greater than its neighbors. Given an integer array with `nums[-1] = nums[n] = -∞` (virtual boundaries), return any peak index. For `[1, 2, 1, 3, 5, 6, 4]` → index 1 (value 2) or index 5 (value 6) both work.

Linear scan finds a peak in O(n). The problem allows O(log n). The array is not globally sorted — you cannot compare mid to a single target — but you *can* compare mid to mid+1. If `nums[mid] < nums[mid + 1]`, you are on an upward slope, so some peak exists at mid+1 or to its right. If `nums[mid] > nums[mid + 1]`, a peak exists at mid or to its left.

## Binary search on slope direction

Use half-open bounds `left = 0`, `right = n - 1`, loop while `left < right`. Compare `nums[mid]` to `nums[mid + 1]`. Ascending at mid → `left = mid + 1`. Descending at mid → `right = mid`. When `left === right`, that index is a peak.

<Steps>
<Step title="Initialize left = 0, right = n - 1">
  A peak is guaranteed to exist — the problem statement says so.
</Step>
<Step title="Mid = left + floor((right - left) / 2)">
  Compare nums[mid] vs nums[mid + 1] — never mid - 1, because mid could be 0.
</Step>
<Step title="Shrink toward the uphill side">
  Ascending → peak is right of mid. Descending → peak is at or left of mid.
</Step>
</Steps>

## Solution

```ts
function findPeakElement(nums: number[]): number {
  let left = 0;
  let right = nums.length - 1;

  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);
    if (nums[mid] < nums[mid + 1]) {
      left = mid + 1;
    } else {
      right = mid;
    }
  }

  return left;
}
```

Time **O(log n)**. Space **O(1)**.

## In an interview

Restate: peak is strictly greater than neighbors; `nums[-1]` and `nums[n]` are -∞; return any valid index. Example: `[1,2,3,1]` → index 2.

Say out loud that this is not standard target search — you compare mid to mid+1 to decide which half still contains a peak. Mention you use `right = mid` (not mid - 1) on the descending side because mid itself could be the peak.

Follow-ups: find peak in 2D matrix, or find element in rotated array (01.08 — different invariant). The bug interviewers watch for is comparing mid to mid-1 when mid = 0, or using `left <= right` with wrong update rules.
