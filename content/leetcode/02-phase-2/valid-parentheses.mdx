## Every close must pair with the nearest open

Given a string containing only `'()'`, `'[]'`, and `'{}'`, determine whether the brackets are valid: every opener eventually closes, in the right order, with no leftovers.

`"()[]{}"` is valid. `"(]"` fails because `]` meets `(` — the most recent unmatched open was `(`, not `[`. `"(["` fails because opens remain after the scan ends. The failure mode is always one of three: wrong closer type, closer with an empty stack, or non-empty stack at the end.

Counting opens and closes separately does not work: `")("` has balanced counts but is invalid. You need **memory of order**, not just totals.

## Stack as pending openers

Scan left to right. On an open bracket, push it — it is waiting for a partner. On a close bracket, the stack must be non-empty and the top must be the matching open. Pop on success; return false on mismatch or empty stack.

The invariant: bottom-to-top of the stack is the nested chain of still-unmatched openers, outermost at the bottom.

<Steps>
<Step title="Push each open bracket onto the stack">
  `'('`, `'['`, `'{'` are the only characters that grow the stack.
</Step>
<Step title="On a close, require stack non-empty and top matches">
  Map `')' → '('`, `']' → '['`, `'}' → '{'`. Mismatch or empty stack → false.
</Step>
<Step title="After the scan, stack must be empty">
  Any remaining openers were never closed.
</Step>
</Steps>

## Solution

```ts
function isValid(s: string): boolean {
  const stack: string[] = [];
  const pairs: Record<string, string> = {
    ")": "(",
    "]": "[",
    "}": "{",
  };

  for (const ch of s) {
    if (ch === "(" || ch === "[" || ch === "{") {
      stack.push(ch);
    } else {
      if (stack.pop() !== pairs[ch]) return false;
    }
  }

  return stack.length === 0;
}
```

Time **O(n)** — one pass, O(1) stack operations per character. Space **O(n)** in the worst case — a string of n open brackets before any close.

## In an interview

Restate with `"([])"` valid and `"(]"` invalid. Confirm only the six bracket characters, no letters, empty string is valid.

Say "stack of pending openers" before coding. Mention all three exit conditions: wrong match, pop from empty, non-empty stack at end.

Follow-ups: include `*` as wildcard, minimum removals to make valid, longest valid substring. Bug interviewers watch for: pushing closers, or comparing with `==` without a map and writing three ugly if-chains that forget one pair.
