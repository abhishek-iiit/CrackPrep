## Infix parsing is overkill for postfix

Given an array of tokens representing an expression in Reverse Polish Notation (postfix), evaluate it. Valid operators: `+`, `-`, `*`, `/`. Division truncates toward zero. For `["2","1","+","3","*"]` → `(2 + 1) * 3 = 9`.

Evaluating infix needs precedence and parentheses — shunting-yard or a parse tree. Postfix has no ambiguity: every operator immediately follows its operands. The natural structure is a **stack**: push numbers, pop two when you hit an operator, push the result.

## Stack-driven evaluation

Walk tokens left to right. If the token is a number, push it. If it is an operator, pop `b` then `a` (order matters for `-` and `/`), compute, push back. After the last token, the stack holds one value — the answer.

<Steps>
<Step title="Initialize an empty number stack">
  Each number token will be pushed here.
</Step>
<Step title="On operator, pop b then a">
  For subtraction and division: result is a op b, not b op a.
</Step>
<Step title="Push result and continue">
  After processing all tokens, stack[0] is the answer.
</Step>
</Steps>

## Solution

```ts
function evalRPN(tokens: string[]): number {
  const stack: number[] = [];

  for (const token of tokens) {
    if (token === "+" || token === "-" || token === "*" || token === "/") {
      const b = stack.pop()!;
      const a = stack.pop()!;
      switch (token) {
        case "+": stack.push(a + b); break;
        case "-": stack.push(a - b); break;
        case "*": stack.push(a * b); break;
        case "/": stack.push(Math.trunc(a / b)); break;
      }
    } else {
      stack.push(Number(token));
    }
  }

  return stack.pop()!;
}
```

Time **O(n)** — one pass over tokens. Space **O(n)** for the stack in the worst case (all numbers before any operator).

<Callout type="warn">
  Use `Math.trunc(a / b)` for division — JavaScript `/` on negatives does not truncate toward zero with `Math.floor`.
</Callout>

## In an interview

Restate: `["4","13","5","/","+"]` → 4 + (13/5) = 6. Confirm division truncates toward zero, expression is always valid, no parentheses.

Say out loud that postfix means every operator applies to the two most recent stack values — pop order is b then a. Mention truncation-toward-zero before coding division.

Follow-ups: Basic Calculator (infix with parentheses — shunting-yard), or design an expression evaluator class. The bug interviewers watch for is pop order (`a - b` vs `b - a`) and using `Math.floor` instead of trunc toward zero.
