## Uniform index is wrong when weights differ

Given positive weights `w[i]`, return index `i` with probability proportional to `w[i]`. `Math.floor(Math.random() * n)` treats every index equally — wrong when `w = [1, 3]`: index 1 should appear three times as often as index 0.

Resampling by expanding weights into a list of repeated indices works for tiny weights but blows up when weights sum to 10⁴ or more. You need **O(log n)** per pick after **O(n)** preprocessing, not O(total weight).

## Prefix sums and one random draw

Build `prefix[i] = sum(w[0..i])`. Total weight `T = prefix[n-1]`. Draw `r` uniformly from `[1, T]` (or `[0, T)` with careful boundaries). Find the smallest index where `prefix[i] >= r` — binary search on a monotonic array.

Example: `w = [1, 3, 2]` → prefix `[1, 4, 6]`. `r = 5` lands in index 2's segment (after 4, before 6).

<Steps>
<Step title="Build cumulative weights in the constructor">
  One pass, O(n) time and space.
</Step>
<Step title="Draw r in [1, total]">
  `Math.floor(Math.random() * total) + 1` for 1-indexed prefix semantics.
</Step>
<Step title="Binary search for the first prefix >= r">
  That index is the sampled outcome.
</Step>
</Steps>

## Solution

```ts
class Solution {
  private prefix: number[] = [];
  private total = 0;

  constructor(w: number[]) {
    this.prefix = new Array(w.length);
    for (let i = 0; i < w.length; i++) {
      this.total += w[i];
      this.prefix[i] = this.total;
    }
  }

  pickIndex(): number {
    const target = Math.floor(Math.random() * this.total) + 1;

    let lo = 0;
    let hi = this.prefix.length - 1;

    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (this.prefix[mid] < target) lo = mid + 1;
      else hi = mid;
    }

    return lo;
  }
}
```

Constructor **O(n)**. Each `pickIndex` is **O(log n)**. Space **O(n)** for the prefix array.

## In an interview

Restate probability: P(i) = w[i] / sum(w). Example `w = [1, 3]`: 25% index 0, 75% index 1. Confirm weights are positive integers.

Draw the number line segmented by cumulative weight before coding. Mention off-by-one on random range — `[1, total]` pairs cleanly with "first prefix ≥ r."

Follow-ups: dynamic weight updates, or streaming picks with unknown n. Bug: using zero-based random against 1-indexed prefixes, or binary searching for exact equality instead of first ≥ target.
