## Paths that turn in the middle

Given a binary tree with integer values (negative nodes allowed), find the maximum sum of any **path**. A path is a sequence of nodes where each adjacent pair shares a parent-child edge. The path does not need to include the root or be purely downward — it can look like left subtree → node → right subtree, bending at an internal node.

Example: tree `[-10, 9, 20, null, null, 15, 7]` — the best path is `15 → 20 → 7` with sum 42, not a root-to-leaf walk.

Brute force — enumerate every path — is exponential. Even counting all root-to-leaf paths is O(n) paths on a balanced tree but each path can be O(n) long; the real issue is that the optimal path may **not** pass through the root at all, so fixing an endpoint at the root misses cases.

The insight: at each node, the best path that **uses this node as the highest point** is `node.val + max(0, leftGain) + max(0, rightGain)`. Left and right gains are the best sums you can bring upward from each child — downward only, because a path cannot fork twice.

## Post-order: gain upward vs answer global

Define `gain(node)` = maximum sum of a downward path starting at `node` and going to some descendant (possibly stopping at `node`). While computing gain, update a global `best` with the crossing path through `node`.

At node `n`:
- `leftGain = max(0, gain(n.left))` — ignore negative contributions
- `rightGain = max(0, gain(n.right))`
- crossing candidate = `n.val + leftGain + rightGain` → maybe update `best`
- return `n.val + max(leftGain, rightGain)` to parent (only one child can continue upward)

<Steps>
<Step title="DFS post-order on each node">
  Compute left and right gains from children first.
</Step>
<Step title="Update global best with the bent path">
  Use both arms plus current value — this is the only place a path turns.
</Step>
<Step title="Return single-arm gain to parent">
  Parent can extend at most one direction through this node.
</Step>
</Steps>

Initialize `best` to `-Infinity` — all-negative trees still have an answer (the least negative single node).

## Solution

```ts
class TreeNode {
  val: number;
  left: TreeNode | null;
  right: TreeNode | null;
  constructor(val?: number, left?: TreeNode | null, right?: TreeNode | null) {
    this.val = val ?? 0;
    this.left = left ?? null;
    this.right = right ?? null;
  }
}

function maxPathSum(root: TreeNode | null): number {
  let best = -Infinity;

  function gain(node: TreeNode | null): number {
    if (node === null) return 0;

    const left = Math.max(0, gain(node.left));
    const right = Math.max(0, gain(node.right));

    best = Math.max(best, node.val + left + right);
    return node.val + Math.max(left, right);
  }

  gain(root);
  return best;
}
```

Time **O(n)** — one visit per node. Space **O(h)** stack, O(n) skewed worst case.

## In an interview

Clarify what "path" means: connected nodes by edges, minimum one node, no requirement to touch root. Walk through a small tree where the answer bends at an internal node, not at the root.

Before coding, state two quantities: "gain going down from a node" vs "best bent path using this node as apex." Say you clamp child contributions at zero so negative subtrees are skipped.

Bug to mention: returning `left + right + val` to the parent (that would allow double forks). Also forgetting that `best` must handle all-negative trees. Follow-ups: print the path; count max-path-sum paths; same logic on a grid.
