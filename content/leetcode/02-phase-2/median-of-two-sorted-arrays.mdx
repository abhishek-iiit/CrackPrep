## Merge is O(m + n); the judge wants O(log(m + n))

Given two sorted arrays, return the median of the combined sorted sequence. For `nums1 = [1,3]`, `nums2 = [2]` → 2.0. For `[1,2]` and `[3,4]` → 2.5.

Merging both arrays takes O(m + n) time and O(m + n) space — too slow when m + n can reach 2 × 10⁵. The median depends only on how elements partition between left and right halves of the merged array, not on materializing the merge.

The reframe: a valid partition splits `nums1` at index `i` and `nums2` at index `j` such that every element on the left is ≤ every element on the right. The median sits at the boundary when left half size equals `(m + n + 1) / 2`.

## Binary search the shorter array's cut

Always binary search on the **shorter** array. Pick cut `i` in `nums1`; `j = halfLen - i` in `nums2` where `halfLen = Math.floor((m + n + 1) / 2)`. Check whether `nums1[i-1] <= nums2[j]` and `nums2[j-1] <= nums1[i]` (treating out-of-bounds as -∞ / +∞). Valid partition → compute median from the four boundary values. Otherwise move `i` left or right.

<Steps>
<Step title="Ensure nums1 is the shorter array; set lo = 0, hi = m">
  Binary search partition index i in nums1 only.
</Step>
<Step title="Compute j = halfLen - i and check cross-boundary order">
  nums1Left ≤ nums2Right and nums2Left ≤ nums1Right → partition valid.
</Step>
<Step title="If nums1Left > nums2Right, i is too large — hi = i - 1">
  If nums2Left > nums1Right, i is too small — lo = i + 1.
</Step>
<Step title="Odd total → max of left boundaries; even → average of max-left and min-right">
  Use -Infinity / Infinity for missing neighbors at edges.
</Step>
</Steps>

## Solution

```ts
function findMedianSortedArrays(nums1: number[], nums2: number[]): number {
  if (nums1.length > nums2.length) {
    return findMedianSortedArrays(nums2, nums1);
  }

  const m = nums1.length;
  const n = nums2.length;
  const halfLen = Math.floor((m + n + 1) / 2);
  let lo = 0;
  let hi = m;

  while (lo <= hi) {
    const i = lo + Math.floor((hi - lo) / 2);
    const j = halfLen - i;

    const nums1Left = i > 0 ? nums1[i - 1] : -Infinity;
    const nums1Right = i < m ? nums1[i] : Infinity;
    const nums2Left = j > 0 ? nums2[j - 1] : -Infinity;
    const nums2Right = j < n ? nums2[j] : Infinity;

    if (nums1Left <= nums2Right && nums2Left <= nums1Right) {
      if ((m + n) % 2 === 1) {
        return Math.max(nums1Left, nums2Left);
      }
      return (Math.max(nums1Left, nums2Left) + Math.min(nums1Right, nums2Right)) / 2;
    } else if (nums1Left > nums2Right) {
      hi = i - 1;
    } else {
      lo = i + 1;
    }
  }

  return 0; // inputs always valid
}
```

Time **O(log(min(m, n)))**. Space **O(1)**.

## In an interview

Restate with both odd and even total length examples. Confirm sorted ascending, m + n ≥ 1, and O(log(m + n)) is expected.

Say out loud that the median is determined by a partition, not a merge — you binary search cut position `i` in the shorter array and derive `j`. Mention the four boundary values and -∞/+∞ sentinels before coding.

Follow-ups: kth element in two sorted arrays (generalize halfLen). The bugs interviewers watch for: searching the longer array (larger search space), wrong halfLen formula for odd vs even, and forgetting to swap so nums1 is shorter.
