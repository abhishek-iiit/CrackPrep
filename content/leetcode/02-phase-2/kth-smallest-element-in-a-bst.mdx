## The kth statistic in sorted order

Given the root of a BST and integer k, return the kth smallest value (1-indexed). A BST's inorder traversal visits nodes in ascending order — the kth stop is the answer.

Brute force: inorder into an array, return `arr[k-1]`. O(n) time, O(n) space. Better: **stop early** once you have counted k nodes — still O(n) worst case (k = n) but O(h + k) in practice and O(h) extra space if iterative.

With up to 10⁴ nodes and many queries, augmenting each node with subtree size gives O(log n) per query — overkill for a single k on one tree unless follow-up explicitly asks for repeated queries.

Edge cases: k = 1 (minimum), k = n (maximum), skewed tree (inorder degenerates to a linked list — still O(n) visits).

## Iterative inorder with a counter

Use a stack. Go left as far as possible, push nodes. Pop, increment count, if count === k return value. Else go to right child and repeat left-spine push.

The invariant: stack holds the path of nodes whose left subtrees are fully processed — standard iterative inorder.

## Solution

```ts
class TreeNode {
  val: number;
  left: TreeNode | null;
  right: TreeNode | null;
  constructor(val?: number, left?: TreeNode | null, right?: TreeNode | null) {
    this.val = val ?? 0;
    this.left = left ?? null;
    this.right = right ?? null;
  }
}

function kthSmallest(root: TreeNode | null, k: number): number {
  const stack: TreeNode[] = [];
  let current = root;
  let count = 0;

  while (current !== null || stack.length > 0) {
    while (current !== null) {
      stack.push(current);
      current = current.left;
    }

    const node = stack.pop()!;
    count++;
    if (count === k) return node.val;

    current = node.right;
  }

  return -1; // k valid per problem constraints
}
```

Time **O(h + k)** — descend to smallest, then k steps; worst **O(n)** when k = n. Space **O(h)** stack.

## In an interview

Confirm 1-indexed k and that the tree is a valid BST (02.18). Example: left spine tree, k = 3 walks down then back.

Explain inorder = sorted order for BST. Say you will iterate with a stack and return on the kth pop — no full array.

Bug: off-by-one on k (0-index vs 1-index); forgetting to traverse right subtree after a pop. Follow-ups: kth largest; multiple queries (augment size); kth in a stream of insertions.
