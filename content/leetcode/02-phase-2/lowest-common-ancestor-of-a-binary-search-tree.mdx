## Use the ordering, not a generic tree walk

Given a BST and nodes `p` and `q`, return their lowest common ancestor — the deepest node that has both as descendants (a node can be ancestor of itself).

On a **general** binary tree, LCA is post-order with parent maps or recursive split logic. On a BST, both targets lie in sorted order relative to every ancestor. Start at root: if both values are smaller, LCA is in the left subtree; if both larger, go right; otherwise the current node is the split point — one value on each side, or one value equals the current node.

Example: tree `[6,2,8,0,4,7,9,null,null,3,5]`, p=2, q=8 → answer 6 (first node where paths to 2 and 8 diverge). p=2, q=4 → answer 2 (because 2 is an ancestor of 4 and p can be the LCA).

That single downward walk is **O(h)** time, O(1) space — no parent pointers, no post-order collection. h is O(log n) balanced, O(n) skewed.

## One pointer from the root

While at `node`:
- If `p.val < node.val && q.val < node.val` → `node = node.left`
- Else if both greater → `node = node.right`
- Else return `node` (split or match)

Order of p and q does not matter — compare both to current.

<Steps>
<Step title="Start at root">
  Both p and q are guaranteed to exist in the tree.
</Step>
<Step title="Move toward the interval gap">
  Both targets strictly on one side → descend that side.
</Step>
<Step title="Stop at first non-descent">
  Current node is between them or equals one — that is the LCA.
</Step>
</Steps>

Generic LCA on a non-BST requires storing paths or a three-flag recursion — strictly more work than this walk.

## Solution

```ts
class TreeNode {
  val: number;
  left: TreeNode | null;
  right: TreeNode | null;
  constructor(val?: number, left?: TreeNode | null, right?: TreeNode | null) {
    this.val = val ?? 0;
    this.left = left ?? null;
    this.right = right ?? null;
  }
}

function lowestCommonAncestor(
  root: TreeNode | null,
  p: TreeNode | null,
  q: TreeNode | null
): TreeNode | null {
  let current = root;

  while (current !== null) {
    if (p!.val < current.val && q!.val < current.val) {
      current = current.left;
    } else if (p!.val > current.val && q!.val > current.val) {
      current = current.right;
    } else {
      return current;
    }
  }

  return null;
}
```

Time **O(h)**. Space **O(1)**.

## In an interview

Clarify: BST property holds; p and q distinct nodes in the tree; return the node reference, not just value. Walk through p ancestor of q — answer is p, not below p.

Say: "I'll walk from the root; if both targets are smaller I go left, both larger I go right, otherwise I'm at the fork."

Bug: assuming p.val < q.val and only comparing one side; using strict inequalities on the wrong branch so you skip the LCA when one node equals current. Follow-ups: LCA on a general binary tree; LCA with parent pointers (02.19's tree without BST); insert then query.
