## You only need k winners, not a full ranking

Given an integer array, return the k most frequent elements. Any order is fine. n can be up to 10⁵, k up to the number of distinct values.

Sorting all unique elements by frequency is O(u log u) where u is distinct count — often acceptable, but it computes a total order you do not need. If u ≈ n and k is 3, you sorted 10⁵ items to learn that three numbers dominate. The constraint n = 10⁵ signals that O(n log n) passes but O(n) or O(n log k) is the intended pattern — especially when follow-ups stream elements or shrink k.

## Count, then select k

**Step 1:** one pass with a hash map → frequency count.

**Step 2:** extract top k. Two standard ways:

1. **Min-heap of size k** keyed by frequency. For each `(num, freq)`, push; if size > k, pop the smallest freq. What remains are the k largest. O(n log k).

2. **Bucket sort by frequency.** Array indexed 0..n where bucket[i] holds numbers appearing exactly i times. Scan buckets from index n down until you collect k elements. O(n) time and space — frequencies are bounded by n.

The heap invariant: the root is the **weakest** survivor among the current top k — any new element must beat it to enter.

## Solution

```ts
function topKFrequent(nums: number[], k: number): number[] {
  const freq = new Map<number, number>();
  for (const n of nums) freq.set(n, (freq.get(n) ?? 0) + 1);

  // Min-heap by frequency — simulated with sort slice for clarity
  const entries = [...freq.entries()];
  entries.sort((a, b) => a[1] - b[1]); // ascending by freq
  return entries.slice(-k).map(([num]) => num);
}
```

Interview implementations usually use a real heap; the sort above is O(u log u) and acceptable when u ≪ n. With a binary min-heap of size k: time **O(n + u log k)**, space **O(u + k)**.

Bucket-sort variant: time **O(n)**, space **O(n)** — buckets indexed by frequency, walk high to low.

## In an interview

Example: `[1,1,1,2,2,3], k=2` → `[1,2]`. Confirm order does not matter and k is always valid.

Say the two phases aloud: count first, select second. Before coding, pick heap vs bucket — if n ≤ 10⁵ and frequencies ≤ n, mention both; default to heap for generality.

Proactive bug: using a **max-heap of all elements** — still O(u log u). The trick is heap **size k**, not heap everything. Another: returning keys from the frequency map without handling ties — any k among tied frequencies is usually acceptable; confirm with interviewer.

Follow-ups: k closest points, top k in a data stream, single-element frequency (just the map).
