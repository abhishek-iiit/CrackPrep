## A cycle turns traversal into an infinite loop

Given the head of a singly linked list, return whether any node is reachable from itself by following `next` pointers. A list `3 → 2 → 0 → -4` with `-4.next` pointing back to `2` has a cycle; `1 → 2 → null` does not.

The naive fix — track every visited node in a `Set` — works and is easy to explain. On a list of length `n` it costs O(n) time and O(n) extra memory. Interviewers ask this problem because there is a second answer that uses two pointer variables and no auxiliary structure, and that answer encodes a real invariant about cyclic motion.

## Floyd's tortoise and hare

Send two pointers into the list: `slow` advances one node per step, `fast` advances two. If there is no cycle, `fast` (or `fast.next`) eventually hits `null`. If there is a cycle, both pointers enter the loop and, inside the loop, the gap between them shrinks by one node every iteration — so they must meet.

<Steps>
<Step title="Initialize both at head">
  `slow = head`, `fast = head`. Do not start `fast` one step ahead; the standard cycle-detection proof assumes they start together.
</Step>
<Step title="Advance until fast exits or they meet">
  While `fast` and `fast.next` are non-null, move `slow` once and `fast` twice. Return `true` on meeting, `false` when `fast` reaches the end.
</Step>
</Steps>

The follow-up — **find the node where the cycle begins** — uses the same meeting point. Reset one pointer to `head`, keep the other at the meeting node, advance both one step at a time; they meet at the cycle entrance. You rarely need to code that variant here, but naming it signals you understand why Floyd works, not just that it works.

## Solution

```ts
class ListNode {
  val: number;
  next: ListNode | null;
  constructor(val?: number, next?: ListNode | null) {
    this.val = val ?? 0;
    this.next = next ?? null;
  }
}

function hasCycle(head: ListNode | null): boolean {
  let slow: ListNode | null = head;
  let fast: ListNode | null = head;

  while (fast !== null && fast.next !== null) {
    slow = slow!.next;
    fast = fast.next.next;
    if (slow === fast) return true;
  }
  return false;
}
```

Time **O(n)**, space **O(1)**. The loop runs at most `n` slow steps before `fast` escapes or they collide.

## In an interview

Restate: singly linked list, detect whether following `next` ever revisits a node. Walk the no-cycle example (`1 → 2 → null` → false) and a small cycle (`tail → node at index 1` → true). Mention the hash-set baseline in one sentence, then say you can do O(1) space with two speeds.

Before coding, state the invariant: inside a cycle, the distance between slow and fast decreases by 1 each round, so they meet. The bug to call out yourself: forgetting `fast.next` in the while condition — `fast.next.next` on a null `fast.next` throws.

Follow-ups: return the cycle-start node; compute cycle length; detect intersection of two lists (01.44 Remove Nth Node shares the two-pointer toolkit).
