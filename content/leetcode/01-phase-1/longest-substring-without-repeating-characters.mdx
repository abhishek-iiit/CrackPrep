## Longest contiguous run with all distinct characters

Given a string `s`, return the length of the longest substring without repeating characters. `"abcabcbb"` → `3` (`"abc"`). `"bbbbb"` → `1`. `"pwwkew"` → `3` (`"wke"` — not `"pwke"` because substrings must be contiguous).

Checking every substring is O(n³) or O(n²) with a set per window — fine for n ≤ 20, not for n up to 5×10⁴. The sliding window keeps a **valid contiguous range** `[left, right]` and expands `right` one char at a time, shrinking `left` only when the new char would duplicate something already inside the window.

## Window invariant: all chars inside are unique

Maintain `lastSeen: Map<char, index>`. When `s[right]` was seen at index `prev` and `prev >= left`, move `left` to `prev + 1` — not `left + 1` one step at a time. That jump preserves O(n) total movement of `left`.

<Steps>
<Step title="Expand right">
  Record `s[right]` in the map at `right`.
</Step>
<Step title="Shrink left on duplicate">
  If char was seen inside the window, set `left = max(left, lastIndex + 1)`.
</Step>
<Step title="Track best">
  `best = max(best, right - left + 1)` after each expansion.
</Step>
</Steps>

Using a fixed-size array of 128 or 256 entries instead of a Map is faster when the alphabet is ASCII — same logic.

## Solution

```ts
function lengthOfLongestSubstring(s: string): number {
  const lastSeen = new Map<string, number>();
  let left = 0;
  let best = 0;

  for (let right = 0; right < s.length; right++) {
    const ch = s[right];
    if (lastSeen.has(ch) && lastSeen.get(ch)! >= left) {
      left = lastSeen.get(ch)! + 1;
    }
    lastSeen.set(ch, right);
    best = Math.max(best, right - left + 1);
  }

  return best;
}
```

Time **O(n)**, space **O(min(n, alphabet))** for the map.

## In an interview

Restate: contiguous substring, all distinct chars, maximize length. Walk `"pwwkew"` — window grows to `"pw"`, second `w` forces left past first `w`, answer stays 3 at `"wke"`.

Before coding, name sliding window invariant. Bug to mention: moving `left` only by one on duplicate (still correct but O(n²)); using `>` instead of `>=` when comparing last index to `left`.
