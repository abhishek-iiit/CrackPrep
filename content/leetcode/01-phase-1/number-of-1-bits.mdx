## Every bit position is a separate question — until it is not

Write a function that takes the unsigned binary representation of an integer and returns the number of `1` bits ('hamming weight'). For `n = 11` (`1011`), the answer is 3.

The naive loop checks all 32 positions: shift right, test the lowest bit, repeat. That is **O(32)** regardless of how sparse the number is. Fine for fixed-width integers, but the problem is really asking: can you skip the zero bits?

There is a classic identity: `n & (n - 1)` clears the **lowest set bit** of `n`. Why? Subtracting 1 flips the trailing zeros and the rightmost 1; ANDing with the original removes exactly that 1. Each application drops one set bit; count how many applications until `n` becomes 0.

For `n = 11` (`1011`): `11 & 10 = 1010` (one bit cleared), `10 & 9 = 1000`, `8 & 7 = 0`. Three steps, three set bits — not 32.

## The n & (n - 1) loop

**Invariant:** each iteration removes exactly the lowest remaining 1-bit; the loop runs once per set bit.

<Steps>
<Step title="Check if n is zero">If yes, return the count accumulated so far.</Step>
<Step title="Clear the lowest set bit">`n = n & (n - 1)` — all higher bits unchanged, one fewer 1.</Step>
<Step title="Increment count and repeat">Stop when `n === 0`.</Step>
</Steps>

Alternative worth knowing: test the lowest bit with `n & 1`, then `n >>>= 1` (unsigned shift). That always runs 32 times for a 32-bit word but is simpler to explain under time pressure.

## Solution

```ts
function hammingWeight(n: number): number {
  let count = 0;
  while (n !== 0) {
    n = n & (n - 1); // clear lowest set bit
    count++;
  }
  return count;
}
```

Time **O(k)** where k is the number of set bits (at most 32). Space **O(1)**.

## In an interview

Restate with an example: `1011` has three ones. Offer two approaches — shift 32 times, or clear the lowest 1 with `n & (n-1)` and count iterations. Implement the clearer one; mention the other.

Follow-ups: "Is n a power of two?" (exactly one set bit → `n & (n-1) === 0`), count bits in a range, or Hamming distance between two integers (XOR then count).

Name the bug before asked: using signed right shift `>>` on negative numbers in JS fills with 1s forever — use `>>>` for unsigned, or stick to `n & (n-1)` which avoids shifting entirely.
