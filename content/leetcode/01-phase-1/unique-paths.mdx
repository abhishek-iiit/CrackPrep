## m×n grid, only right and down — how many routes?

A robot sits at the top-left of an `m × n` grid and wants the bottom-right. It may move only **right** or **down**. How many distinct paths?

For `3 × 7`, brute force tries every binary sequence of 6 rights and 2 downs among 8 moves — that is **C(8,2) = 28`**, but enumerating sequences for `23 × 12` is absurd. The grid structure means paths share prefixes: every path to cell `(i,j)` passes through either `(i-1,j)` or `(i,j-1)`.

## Grid DP: add incoming paths

`dp[i][j]` = number of paths to `(i,j)`. First row and column are all `1` (only one way to walk a straight line). Interior: `dp[i][j] = dp[i-1][j] + dp[i][j-1]`.

The invariant: every path to `(i,j)` arrives from exactly one of those two neighbors — no diagonals, no revisits.

You can roll the table to one row: iterate rows, update a 1D array left-to-right. Same recurrence, **O(n)** space instead of **O(mn)**.

### Combinatorics shortcut

Any valid path uses exactly `(m-1)` downs and `(n-1)` rights — `(m+n-2)` total steps. Choose which steps are downs: **C(m+n-2, m-1)**. For `3 × 7`, that is C(8,2) = 28. Same answer, **O(min(m,n))** time if you compute the binomial carefully with division to avoid overflow (interviewers often accept DP for safety).

## Solution

```ts
function uniquePaths(m: number, n: number): number &#123;
  const dp = new Array<number>(n).fill(1);

  for (let i = 1; i < m; i++) &#123;
    for (let j = 1; j < n; j++) &#123;
      dp[j] += dp[j - 1];
    &#125;
  &#125;
  return dp[n - 1];
&#125;
```

Time **O(m × n)**, space **O(n)**. A full matrix uses **O(mn)** space — fine for `m,n ≤ 100`.

## In an interview

Draw a 3×3 grid, trace two paths, then say: "Every cell sums paths from top and left; edges are 1." Optionally mention the binomial identity as a sanity check.

Follow-ups: **Unique Paths II** with obstacles (`0` cells → skip, `dp[i][j]=0`), minimum path sum, or "what if you can move in four directions?" (four-direction invalidates this dp). Edge: `1×1` grid → 1 path.

Mention overflow on combinatorics for large grids if you use the formula — dp with bigint or mod is safer when they specify it.
