## Addition is two separate jobs

Given two integers `a` and `b`, return their sum — but you cannot use `+` or `-`. The constraint is not about arithmetic being hard; it is about showing you understand what addition actually does at the bit level.

At each bit position, two inputs produce a **sum bit** (0 if they differ, 1 if they agree) and a **carry out** (1 only when both are 1). Grade-school addition processes column by column, propagating carries leftward. That propagation is exactly what `+` hides from you. The interview wants the decomposition: compute sum bits and carry bits separately, then repeat until carries vanish.

For `a = 5` (`101`) and `b = 3` (`011`): XOR gives `110` (partial sum, missing the carry into bit 2), AND-shift gives `010` (the carry). XOR again → `100`, carry → `100`. One more round → sum `1000` = 8. Three iterations for 3-bit numbers; at most 32 for 32-bit ints.

## XOR for sum bits, AND-shift for carries

**Invariant:** at each step, `a` holds the bits that are correct so far (sum without pending carries), and `b` holds carries still to propagate. When `b` becomes 0, `a` is the answer.

- **XOR (`a ^ b`):** sum bits at every position, ignoring carries from lower bits.
- **AND then left-shift (`(a & b) << 1`):** positions where both bits were 1 become carries in the next column.

<Steps>
<Step title="Save carries before overwriting">`carry = (a & b) << 1` — positions where both bits were 1 become carries in the next column.</Step>
<Step title="XOR into partial sum">`a = a ^ b` — sum bits at every position, ignoring incoming carries.</Step>
<Step title="Propagate carries">Set `b = carry` and repeat until `b === 0`. At most 32 rounds for 32-bit integers.</Step>
</Steps>

<Callout type="gotcha">
JavaScript/TypeScript numbers are IEEE-754 doubles, but LeetCode treats inputs as **signed 32-bit integers** and expects a signed 32-bit result. After the loop, if you need strict 32-bit behavior on negative numbers, mask with `0xffffffff` and re-sign-extend — most accepted solutions on this problem skip that because test cases stay in the easy range, but mention it if the interviewer asks about `-1 + 1`.
</Callout>

## Solution

```ts
function getSum(a: number, b: number): number {
  while (b !== 0) {
    const carry = (a & b) << 1;
    a = a ^ b;
    b = carry;
  }
  return a;
}
```

Time **O(1)** — bounded by word width (32 iterations max). Space **O(1)**.

## In an interview

Restate: sum two integers without `+` or `-`. Walk through `5 + 3` on paper — XOR gives partial sum, AND-shift gives carry, loop until carry is zero. Code the three-line loop. Mention that this mirrors a half-adder (XOR + AND) chained into a ripple-carry adder.

Follow-ups: subtract without `-` (add the two's complement: `~b + 1` via the same loop), multiply without `*` (Russian peasant / shift-add), or "why does this terminate?" (carries move left and eventually fall off the top).

The bug to name first: forgetting to shift the carry left — `(a & b)` without `<< 1` double-counts at the same bit position instead of propagating to the next.
