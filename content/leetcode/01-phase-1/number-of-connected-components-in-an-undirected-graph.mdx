## How many islands in a node graph

Given `n` nodes and undirected edges, count connected components. With `n = 5` and edges `[[0,1],[1,2],[3,4]]`, nodes `{0,1,2}` form one component and `{3,4}` another — answer **2**. Node `3` with no edges is still its own component of size 1.

The brute force — for each node, BFS to mark everything reachable and increment a counter — is exactly the right idea. Each node is visited once; each edge is traversed twice in an adjacency list. The only design choice is whether you express "same component" with a visited array, a queue, or Union-Find merges.

## One launch per unseen node

Build an adjacency list from the edge pairs (undirected: add both directions). Loop `i` from `0` to `n-1`. If `i` is unvisited, increment `count` and DFS/BFS from `i` to paint the whole component. When the loop finishes, `count` is the number of components.

Union-Find alternative: start with `n` components, union each edge, return the number of distinct roots after path compression. Same asymptotics, different ergonomics when edges arrive incrementally.

<Steps>
<Step title="Build adjacency">
For each `[u, v]`, push `v` onto `adj[u]` and `u` onto `adj[v]`.
</Step>
<Step title="Scan all nodes">
If node `i` is unvisited, run DFS from `i` and increment the component counter.
</Step>
<Step title="DFS marks the component">
Visit neighbors recursively; mark each node visited before exploring edges to avoid infinite loops.
</Step>
</Steps>

## Solution

```ts
function countComponents(n: number, edges: number[][]): number {
  const adj: number[][] = Array.from({ length: n }, () => []);
  for (const [u, v] of edges) {
    adj[u].push(v);
    adj[v].push(u);
  }

  const visited = new Array<boolean>(n).fill(false);
  let components = 0;

  const dfs = (node: number): void => {
    visited[node] = true;
    for (const nei of adj[node]) {
      if (!visited[nei]) dfs(nei);
    }
  };

  for (let i = 0; i < n; i++) {
    if (!visited[i]) {
      components++;
      dfs(i);
    }
  }

  return components;
}
```

Time **O(n + e)** where **e** is the number of edges. Space **O(n + e)** for adjacency and the visited array (recursion stack O(n) in the worst case).

## In an interview

Restate with a tiny example; confirm isolated nodes count as components. Say you will iterate all nodes and DFS from each unvisited one — component count equals the number of launches. Complexity O(n + e) because each node and edge is touched once.

Follow-ups: return sizes of each component, count in a directed graph (strongly connected components — different algorithm), dynamic connectivity. Mention marking visited **before** recursing into neighbors — revisiting without a visited check cycles forever on undirected graphs.
