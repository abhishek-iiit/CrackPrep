## Keep as many as possible, remove the rest

Given `[[1,2],[2,3],[3,4],[1,3]]`, remove one interval so the rest are pairwise non-overlapping. Removing `[1,3]` leaves three compatible intervals — answer **1**. The naive approach tries every subset — exponential.

This is interval scheduling: maximize the number of non-overlapping intervals, equivalently minimize removals. Greedy by **earliest finish time** is optimal: sort by end, take an interval if its start is at or after the last kept end, otherwise skip it (count a removal).

## Greedy by end time

Sort intervals by `end` ascending. Track `prevEnd`, the end of the last kept interval. For each `[start, end]`:

- If `start >= prevEnd`, keep it — set `prevEnd = end`.
- Else overlap with the last kept — increment `removals` (drop the current one).

Why end time, not start? An interval that ends early leaves the most room for what follows. Counterexample mindset: choosing the shorter start-first interval can block two later intervals.

<Steps>
<Step title="Sort by end">
Earliest-finishing intervals get first consideration.
</Step>
<Step title="Keep if compatible">
`start >= prevEnd` means no overlap with the last kept interval — keep and update `prevEnd`.
</Step>
<Step title="Else remove">
Overlapping current interval cannot coexist with the last kept one — drop it and count one removal.
</Step>
</Steps>

## Solution

```ts
function eraseOverlapIntervals(intervals: number[][]): number {
  if (intervals.length === 0) return 0;

  intervals.sort((a, b) => a[1] - b[1]);
  let removals = 0;
  let prevEnd = intervals[0][1];

  for (let i = 1; i < intervals.length; i++) {
    const [start, end] = intervals[i];
    if (start >= prevEnd) {
      prevEnd = end;
    } else {
      removals++;
    }
  }

  return removals;
}
```

Time **O(n log n)** for sort, **O(n)** scan. Space **O(1)** beyond sort (or O(n) if sort copies).

<Callout type="gotcha">
Sorting by start and greedily picking the earliest start is **not** optimal. `[[1,100],[2,3],[4,5]]` — start-first keeps `[1,100]` and removes two; end-first keeps `[2,3]` and `[4,5]` and removes one.
</Callout>

## In an interview

Rephrase: minimum intervals to delete so none overlap. Note equivalence to maximum non-overlapping subset. Propose sort by end, greedy keep. Walk `[[1,2],[2,3],[3,4],[1,3]]` — end-sorted order makes the conflict with `[1,3]` obvious.

Follow-ups: return the kept set, weighted job scheduling, merge then count (wrong tool). State the exchange argument in one sentence: replacing a kept interval with one that ends later cannot increase room for future intervals.
