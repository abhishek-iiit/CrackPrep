## Two indices, one pass budget

Given an integer array and a target, return the indices of two distinct elements that sum to the target. Exactly one solution exists, and you may not reuse the same element twice.

The brute force is the nested loop: for each index `i`, scan every `j > i` and check whether `nums[i] + nums[j] === target`. On an array of length 10⁴ that is on the order of 10⁸ comparisons — fine for a toy input, TLE on the judge. The constraint n ≤ 10⁴ is the hint that linear time is expected.

The reframe: at index `i` you are not searching for *any* partner — you are searching for one specific value, `target - nums[i]`. That is a lookup, not a scan.

## One map, one forward pass

Maintain a hash map from **value → index seen so far**. Walk left to right. At each position, compute the complement. If the complement is already in the map, return `[map.get(complement), i]`. Otherwise store the current value and index, then continue.

The invariant: every key in the map appeared at an index strictly before the current one. You never pair an element with itself because you check the map *before* inserting the current value.

## Solution

```ts
function twoSum(nums: number[], target: number): number[] {
  const seen = new Map<number, number>();

  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (seen.has(complement)) {
      return [seen.get(complement)!, i];
    }
    seen.set(nums[i], i);
  }

  return []; // problem guarantees one solution
}
```

Time **O(n)** — one pass, O(1) expected map operations. Space **O(n)** for the map in the worst case (no match until the end).

## In an interview

Restate the problem with a concrete example: `nums = [2, 7, 11, 15], target = 9` → `[0, 1]`. Confirm constraints: one guaranteed solution, same element cannot be used twice, return indices not values.

Say out loud that brute force is O(n²) and that the target minus current value turns the inner loop into a hash lookup. Mention the self-pair bug before coding: check the map before inserting the current element.

Follow-ups to expect: sorted input (two pointers), return all pairs, or 01.09 3Sum (sort + two pointers on the reduced subproblem). The bug interviewers watch for is using the same index twice when `nums[i] === complement` and duplicates exist.
