## Can one person attend everything?

Each meeting is `[start, end]`. Given `[[0,30],[5,10],[15,20]]`, meetings 2 and 3 overlap with meeting 1 — return **false**. For `[[7,10],[2,4]]`, no overlap after sorting — return **true**.

You do not need to merge intervals or count rooms. You only need to know whether **any** two intervals intersect. After sorting by start, an overlap exists iff some interval starts before the previous one ends.

## Sort and scan neighbors

Sort by `start`. For `i` from 1 to n−1, if `intervals[i][0] < intervals[i-1][1]`, two meetings conflict — return false. If the loop completes, return true.

Why `<` and not `<=`? Back-to-back meetings `[0,10]` and `[10,20]` share an endpoint; one person can leave one and enter the other — no conflict. LeetCode uses half-open semantics in spirit: touching ends are allowed.

<Steps>
<Step title="Sort by start">
Order meetings chronologically by start time.
</Step>
<Step title="Compare adjacent pairs">
Only sorted neighbors can overlap — if none of them conflict, the set is conflict-free.
</Step>
<Step title="Early exit on conflict">
First `start < prevEnd` proves attendance is impossible.
</Step>
</Steps>

## Solution

```ts
function canAttendMeetings(intervals: number[][]): boolean {
  intervals.sort((a, b) => a[0] - b[0]);

  for (let i = 1; i < intervals.length; i++) {
    if (intervals[i][0] < intervals[i - 1][1]) return false;
  }
  return true;
}
```

Time **O(n log n)** for sort, **O(n)** scan. Space **O(1)** beyond sort.

## In an interview

Restate: one person, can they attend all meetings? Empty list returns true. Sort by start, walk adjacent pairs. O(n log n). This is the gateway to 01.39 — say so explicitly if time remains.

Follow-ups: return the conflicting pair, merge overlapping meetings (01.36), minimum rooms (01.39). Clarify touching endpoints: `[1,2]` and `[2,3]` should return true. Bug: using `<=` on the end comparison and rejecting valid back-to-back schedules.
