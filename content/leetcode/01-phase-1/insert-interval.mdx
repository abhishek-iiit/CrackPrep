## One new interval into a sorted list

You have non-overlapping intervals sorted by start, e.g. `[[1,3],[6,9]]`, and must insert `[2,5]`. The result is `[[1,5],[6,9]]` — the newcomer overlaps the first interval and merges into it. Inserting `[4,7]` would bridge `[1,3]` and `[6,9]` into `[1,9]`. Inserting `[10,12]` appends cleanly with no merge.

Re-sorting the whole list after insert works but wastes the sorted invariant — O(n log n) instead of O(n). The linear approach treats the list as three zones: intervals ending before the new one starts, intervals that overlap the new one (possibly many), intervals starting after the merged block ends.

## Three-phase single pass

Overlap test for `[a,b]` and `[c,d]`: they intersect iff `a <= d && c <= b`. Walk the list:

1. **Before:** while `intervals[i][1] < newInterval[0]`, push `intervals[i]`.
2. **Overlap:** while intervals overlap `newInterval`, expand `newInterval` to `[min(starts), max(ends)]`.
3. **After:** push the merged interval once, then copy the rest.

<Steps>
<Step title="Copy strictly before">
Intervals whose end is strictly less than `newInterval[0]` cannot overlap — append unchanged.
</Step>
<Step title="Merge overlapping block">
While `intervals[i][0] <= newInterval[1]`, widen `newInterval` to cover both ends.
</Step>
<Step title="Append merged + tail">
Push the widened `newInterval`, then append remaining intervals.
</Step>
</Steps>

## Solution

```ts
function insert(
  intervals: number[][],
  newInterval: number[]
): number[][] {
  const result: number[][] = [];
  let i = 0;
  const n = intervals.length;

  while (i < n && intervals[i][1] < newInterval[0]) {
    result.push(intervals[i++]);
  }

  while (i < n && intervals[i][0] <= newInterval[1]) {
    newInterval = [
      Math.min(newInterval[0], intervals[i][0]),
      Math.max(newInterval[1], intervals[i][1]),
    ];
    i++;
  }
  result.push(newInterval);

  while (i < n) result.push(intervals[i++]);
  return result;
}
```

Time **O(n)**, space **O(n)** for the output (excluding input).

<Callout type="tip">
If the input were not sorted, sort by start first — then this same merge loop applies. 01.36 Merge Intervals is the batch version of the overlap-merge step.
</Callout>

## In an interview

Confirm: sorted, non-overlapping input; inclusive bounds `[start, end]`; insert one interval; return merged sorted list. Walk `[1,3],[6,9]` + `[2,5]`. Describe three phases before coding. Overlap condition: `interval[i][0] <= newEnd` while merging.

Follow-ups: delete an interval, insert many, binary search to find insertion point (still linear merge in worst case). Bug to flag: using `<` instead of `<=` on the overlap check and splitting intervals that should merge at a touching endpoint — clarify whether `[1,2]` and `[2,3]` merge (usually yes for this problem family).
