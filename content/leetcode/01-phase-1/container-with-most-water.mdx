## Area between two vertical lines

Given `height[i]` as the height of a vertical line at x = i, pick two lines forming a container with the x-axis. Water area equals `min(height[i], height[j]) × (j − i)`. Return maximum area. n ≥ 2.

Brute force tries every pair (i, j) — O(n²). With n = 10⁵ that is about 5×10⁹ evaluations. Two pointers from both ends cut that to O(n) with one greedy move rule.

The bottleneck is always the **shorter** line. Widening the window by moving the taller pointer inward cannot increase area — width shrinks and height is still capped by the shorter side you kept.

## Inward from both ends

Initialize `left = 0`, `right = n - 1`, `maxArea = 0`.

While `left < right`: compute area with current pair, update max. Move the pointer at the **shorter** height inward by one. If equal height, either move works — pick one consistently.

The invariant: no optimal pair is missed by always discarding the shorter side, because any container that kept the shorter line and moved the taller line only loses width without gaining height.

Example `[1, 8, 6, 2, 5, 4, 8, 3, 7]`: best area 49 from heights 8 and 7 with width 7.

## Solution

```ts
function maxArea(height: number[]): number {
  let left = 0;
  let right = height.length - 1;
  let maxArea = 0;

  while (left < right) {
    const h = Math.min(height[left], height[right]);
    const w = right - left;
    maxArea = Math.max(maxArea, h * w);

    if (height[left] < height[right]) {
      left++;
    } else {
      right--;
    }
  }

  return maxArea;
}
```

Time **O(n)**, space **O(1)**.

## In an interview

Restate area formula with min height × width. Example `[1,8,6,2,5,4,8,3,7]` → 49.

Explain why moving the taller line cannot help before coding. Mention equal heights — move either side.

Follow-ups: return indices, 03.34 Trapping Rain Water, prove correctness. Bug: always moving left regardless of height — misses the greedy proof and gets wrong answers on asymmetric arrays.
