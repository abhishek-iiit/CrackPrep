## Exponential recursion hides a linear table

You climb a staircase of `n` steps. Each move you take 1 or 2 steps. How many distinct ways to reach the top?

For `n = 3`: paths are `1+1+1`, `1+2`, `2+1` → **3** ways. For `n = 4`: **5** ways. The sequence 1, 2, 3, 5, 8… is Fibonacci shifted by one.

Naive recursion: from step `i`, try `ways(i-1) + ways(i-2)`. Without memoization that revisits the same subproblems exponentially — `ways(5)` fans into `ways(4)` and `ways(3)`, and `ways(4)` calls `ways(3)` again. Time explodes to **O(2ⁿ)**. The fix is not a smarter tree walk; it is recognizing that `ways(i)` depends only on two predecessors, so you fill a table once.

## Recurrence: ways(i) = ways(i-1) + ways(i-2)

**Invariant:** after processing step `i`, you know the total ways to stand exactly on step `i`.

To land on step `i`, your last move was either from `i-1` (one step) or from `i-2` (two steps). Those two sets of paths do not overlap — different last move — so add them.

Base cases: one way to stand on step 0 (do nothing), one way to reach step 1 (single 1-step).

<Steps>
<Step title="Handle n ≤ 2 directly">`n === 1` → 1; `n === 2` → 2.</Step>
<Step title="Track prev and curr">`prev = 1` (ways at i-2), `curr = 2` (ways at i-1).</Step>
<Step title="Loop i from 3 to n">`next = prev + curr`, slide window: `prev = curr`, `curr = next`.</Step>
<Step title="Return curr">Ways to reach step n.</Step>
</Steps>

## Solution

```ts
function climbStairs(n: number): number {
  if (n <= 2) return n;
  let prev = 1; // ways at step 1
  let curr = 2; // ways at step 2
  for (let i = 3; i <= n; i++) {
    const next = prev + curr;
    prev = curr;
    curr = next;
  }
  return curr;
}
```

Time **O(n)**. Space **O(1)** — only two rolling variables. Matrix exponentiation can reach **O(log n)** for huge n — overkill here where n ≤ 45.

## In an interview

Restate: count ways to climb n steps with 1- or 2-step moves. Write the recurrence before code: "to reach i, I came from i-1 or i-2, so f(i) = f(i-1) + f(i-2)." Base cases: f(1)=1, f(2)=2. Implement rolling variables.

Follow-ups: allow 1-, 2-, or 3-step moves (tribonacci), minimum cost when steps have weights (01.17-adjacent Min Cost Climbing Stairs), or "what is the time without memo?" to expose O(2ⁿ).

Bug to mention: off-by-one on base cases — `n = 1` should return 1, not 0; confusing "step 0" with "zero ways."
