## k sorted streams, not two

Given an array of `k` ascending linked lists, merge them into one ascending list. With `k = 3` and lists `[1,4,5]`, `[1,3,4]`, `[2,6]`, the result is `[1,1,2,3,4,4,5,6]`.

01.42 Merge Two Sorted Lists solves the `k = 2` case in linear time. Repeating that merge — fold lists left to right — works but can degrade: merging a growing list with a fresh one repeatedly touches the same nodes many times. When `k` is large and lists are balanced, the total work can approach **O(n k)** instead of the **O(n log k)** you get if each of the `n` total nodes participates in only **log k** heap operations.

## Min-heap: always pick the smallest current head

Push the head of every non-empty list onto a min-heap ordered by node value ( tie-break by list index if you need stability). Pop the smallest, append it to the result, push its `next` if any. Stop when the heap is empty.

<Steps>
<Step title="Seed the heap">
  For each list, if `head !== null`, push `{ node: head, idx: i }`. Empty lists contribute nothing.
</Step>
<Step title="Pop, link, push next">
  Pop minimum node `u`, attach to tail, push `u.next` if non-null. The heap always holds at most `k` elements.
</Step>
<Step title="Return dummy.next">
  Same dummy-tail pattern as two-list merge; only the source of the next minimum changes.
</Step>
</Steps>

Without a built-in heap in TypeScript, simulate with an array and `sort` on each push — acceptable for interview clarity on small `k`, but say out loud that a binary heap gives the proper **O(log k)** per operation.

## Solution

```ts
class ListNode {
  val: number;
  next: ListNode | null;
  constructor(val?: number, next?: ListNode | null) {
    this.val = val ?? 0;
    this.next = next ?? null;
  }
}

function mergeKLists(lists: Array<ListNode | null>): ListNode | null {
  const heap: ListNode[] = lists.filter((h): h is ListNode => h !== null);

  const popMin = (): ListNode | undefined => {
    if (heap.length === 0) return undefined;
    heap.sort((a, b) => a.val - b.val);
    return heap.shift();
  };

  const push = (node: ListNode | null): void => {
    if (node !== null) heap.push(node);
  };

  const dummy = new ListNode();
  let tail: ListNode = dummy;

  lists.forEach((h) => push(h));

  while (heap.length > 0) {
    const node = popMin()!;
    tail.next = node;
    tail = node;
    push(node.next);
  }

  return dummy.next;
}
```

Time **O(n k log k)** with array-sort heap simulation; **O(n log k)** with a real min-heap. Space **O(k)** for the heap plus **O(1)** for list rewiring.

<Callout type="tip">
Divide-and-conquer merge — pair lists, merge pairs, repeat — runs in **O(n log k)** time with **O(1)** extra space if you merge in place, and avoids heap boilerplate. Mention it even if you code the heap version.
</Callout>

## In an interview

Clarify: `k` lists, each sorted ascending, return one merged list. Edge cases: `k = 0`, all empty lists (return null), one nonempty list. Compare 01.42 two-list merge as the base operation.

Before coding, pick heap vs divide-and-conquer and state complexity. Self-flag: forgetting null heads when seeding; pop without pushing `next`; returning the dummy node.

Follow-ups: merge sorted arrays instead of lists; external merge of files larger than RAM; k-way merge is the read path of an LSM compaction — same shape, different scale.
