## Same width cannot nest — sort kills the tie trap

Given envelopes `[width, height]`, one fits inside another only if **both** dimensions are strictly smaller. Find the maximum nesting depth (Russian doll count).

`[[5,4],[6,4],[6,7],[2,3]]` → 3: `[2,3]` → `[5,4]` → `[6,7]`.

O(n²) DP on pairs works for n ≤ 10⁴ but barely. The standard reduction: sort envelopes by **width ascending**, and for equal width by **height descending**. Now nesting is strictly increasing in both dimensions iff heights form a **strictly increasing subsequence** in sorted order.

Why descending height on width ties? `[6,4]` and `[6,7]` share width — only one can appear in a valid chain. Sorting height descending keeps the larger height first so LIS cannot pick both.

## Sort + LIS with binary search

After sort, run longest increasing subsequence on heights using the patience-sorting / `tails` array method from 01.18 Longest Increasing Subsequence — O(n log n).

For each envelope `(w, h)`, binary search `tails` for leftmost `>= h`, replace or append. `tails.length` is the answer.

## Solution

```ts
function maxEnvelopes(envelopes: number[][]): number {
  envelopes.sort((a, b) =>
    a[0] === b[0] ? b[1] - a[1] : a[0] - b[0]
  );

  const tails: number[] = [];

  for (const [, h] of envelopes) {
    let lo = 0;
    let hi = tails.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (tails[mid] < h) lo = mid + 1;
      else hi = mid;
    }
    if (lo === tails.length) tails.push(h);
    else tails[lo] = h;
  }

  return tails.length;
}
```

Time **O(n log n)** from sort plus LIS. Space **O(n)** for sort and tails.
