## k is the knob — and sometimes it does not matter

Given an integer `k` and daily prices, maximize profit with **at most k** complete transactions. Same rules as 03.42: no overlapping holds, sell before the next buy.

03.42's four scalars are the k = 2 special case. For general k, maintain two arrays of length `k + 1`:

- `buy[j]` — minimum cost to enter the j-th transaction (best effective buy price so far)
- `sell[j]` — maximum profit after completing j transactions

For each price, update transactions **from k down to 1** so same-day sells do not fund same-day buys incorrectly:

```
sell[j] = max(sell[j], buy[j] + price)
buy[j]  = min(buy[j], sell[j-1] - price)
```

`sell[0] = 0` — zero transactions yield zero profit. `buy[j]` starts at `Infinity`.

## The k ≥ n/2 shortcut

You cannot complete more than one transaction per two days in the worst case — at most `⌊n/2⌋` meaningful transactions exist. When `k >= n/2`, the cap is irrelevant: capture **every upward slope** greedily (same as unlimited transactions).

```text
profit += max(0, prices[i] - prices[i-1])  for i = 1..n-1
```

For `[1,2,3,4,5]` with k = 2, greedy uphill gives 4 — same as one long hold. For k = 100 on a length-5 array, skip the DP entirely.

## Solution

```ts
function maxProfit(k: number, prices: number[]): number {
  const n = prices.length;
  if (k >= Math.floor(n / 2)) {
    let profit = 0;
    for (let i = 1; i < n; i++) {
      if (prices[i] > prices[i - 1]) profit += prices[i] - prices[i - 1];
    }
    return profit;
  }

  const buy = new Array<number>(k + 1).fill(Infinity);
  const sell = new Array<number>(k + 1).fill(0);

  for (const price of prices) {
    for (let j = k; j >= 1; j--) {
      sell[j] = Math.max(sell[j], buy[j] + price);
      buy[j] = Math.min(buy[j], sell[j - 1] - price);
    }
  }

  return sell[k];
}
```

Time **O(n × k)**. Space **O(k)**.

## In an interview

State the recurrence aloud: completing transaction j requires either keeping the best prior sell[j] or selling a position bought at buy[j]. Funding buy[j] uses sell[j-1] profit.

Name the k ≥ n/2 optimization before coding — it signals you understand when the constraint is vacuous.

Bug: iterating j from 1 to k instead of k down to 1, allowing same-day buy funded by same-day sell. Follow-ups: transaction fee per trade, mandatory cooldown day, return actual trade list.
