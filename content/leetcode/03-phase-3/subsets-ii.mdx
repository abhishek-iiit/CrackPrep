## Same multiset, many arrays — brute force dedup is too late

Given an integer array that **may contain duplicates**, return all **unique** subsets. For `[1, 2, 2]` the answer is `[[]`, `[1]`, `[1,2]`, `[1,2,2]`, `[2]`, `[2,2]` — six subsets, not eight. Without dedup, choosing the first `2` then the second `2` and choosing them in reverse order both produce `[2,2]` as separate branches.

Sorting is the setup. Once equal values sit adjacent, you can enforce: at recursion depth `d`, if `nums[i] === nums[i-1]` and you skipped picking `nums[i-1]` at this depth, skip `nums[i]` too. That rule generates each subset once without a Set at the end.

## Subsets template plus skip-duplicate

Same skeleton as 03.02 Subsets: push `path` at every node, loop from `start`, recurse with `i + 1`. After sorting, add inside the for-loop:

`if (i > start && nums[i] === nums[i - 1]) continue;`

The invariant: among equal values, you only branch on the **first unused copy** at each depth. Picking the second `2` without picking the first at this level would duplicate subsets already explored via the first `2`.

<Steps>
<Step title="Sort nums">
  Duplicates must be adjacent for the skip rule to fire.
</Step>
<Step title="Push path, extend from start">
  Identical to Subsets — every prefix is recorded.
</Step>
<Step title="Skip equal neighbor at same depth">
  When `i > start` and `nums[i] === nums[i-1]`, continue. You already explored "skip this duplicate" via the previous iteration.
</Step>
</Steps>

<Callout type="gotcha">
The condition is `i > start`, not `i > 0`. At the root you may still pick any copy of a duplicated value — the skip only prevents choosing the second 2 when you chose not to choose the first 2 at this same depth.
</Callout>

## Solution

```ts
function subsetsWithDup(nums: number[]): number[][] {
  nums.sort((a, b) => a - b);
  const result: number[][] = [];
  const path: number[] = [];

  function backtrack(start: number): void {
    result.push([...path]);
    for (let i = start; i < nums.length; i++) {
      if (i > start && nums[i] === nums[i - 1]) continue;
      path.push(nums[i]);
      backtrack(i + 1);
      path.pop();
    }
  }

  backtrack(0);
  return result;
}
```

Time **O(n × 2^n)** worst case — still exponential in n, with less constant duplication on repeated values. Space **O(n)** recursion depth, excluding output.

## In an interview

Restate: duplicates allowed, unique subsets only. Walk `[1,2,2]` and show why two paths reach `[2,2]` without the skip rule.

Say you will sort first, then reuse Subsets with `i > start && nums[i] === nums[i-1]` skip — one sentence that signals you know the duplicate-combination family.

Follow-ups: **Combination Sum II** (each candidate once plus target), **Permutations II** (used array plus skip at depth). Bug to mention: using `i > 0` instead of `i > start`, which incorrectly kills valid subsets at the root.
