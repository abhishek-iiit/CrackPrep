## The ocean rises — your path must stay underwater together

An `n × n` grid gives elevation at each cell. You start at `(0,0)` and want `(n-1, n-1)`. At time `t`, water level is `t`; you can swim through cells with elevation `≤ t`. Find the **minimum** `t` when a path exists.

Grid `[[0,2],[1,3]]`: at `t = 3` you can go `(0,0) → (1,0) → (1,1)` because max elevation on that path is 3. At `t = 2` the destination cell is still dry. Answer: **3**.

Naive BFS on time layers — simulate water rising one unit at a time — can revisit the grid many times. The insight is monotonicity: if you can swim at level `T`, you can swim at any `T' > T`. That invites **binary search on the answer** with a reachability check, or a single **Dijkstra** where edge cost is the max elevation you must tolerate along the path.

## Minimax path on a grid

Two equivalent views:

1. **Binary search `t`** from `0` to `n² - 1` (or max grid value). For each mid, BFS/DFS flood from `(0,0)` through cells `≤ mid`; succeed if `(n-1, n-1)` is reached.

2. **Dijkstra with priority = path max elevation**. Start with `(0,0)` at cost `grid[0][0]`. Pop smallest cost cell; relax 4-neighbors with `newCost = max(currentCost, grid[neighbor])`. First time you pop `(n-1, n-1)` is the answer.

The invariant: the optimal path's bottleneck cell determines the minimum feasible water level — same as "widest path" or minimax shortest path.

<Steps>
<Step title="Binary search bounds">
`lo = grid[0][0]`, `hi = max cell value` (or n² − 1). Answer lies in `[lo, hi]`.
</Step>
<Step title="Feasibility check">
`canSwim(t)`: BFS from start, only visit cells with `grid[r][c] <= t`, 4-directional.
</Step>
<Step title="Shrink search space">
If feasible at `mid`, try `hi = mid`; else `lo = mid + 1`. Return `lo`.
</Step>
</Steps>

## Solution

```ts
function swimInWater(grid: number[][]): number {
  const n = grid.length;
  const dirs = [0, 1, 0, -1, 0];

  function canSwim(t: number): boolean {
    if (grid[0][0] > t || grid[n - 1][n - 1] > t) return false;
    const seen = Array.from({ length: n }, () => new Array(n).fill(false));
    const q: [number, number][] = [[0, 0]];
    seen[0][0] = true;

    while (q.length) {
      const [r, c] = q.shift()!;
      if (r === n - 1 && c === n - 1) return true;
      for (let d = 0; d < 4; d++) {
        const nr = r + dirs[d], nc = c + dirs[d + 1];
        if (nr < 0 || nr >= n || nc < 0 || nc >= n || seen[nr][nc]) continue;
        if (grid[nr][nc] > t) continue;
        seen[nr][nc] = true;
        q.push([nr, nc]);
      }
    }
    return false;
  }

  let lo = Math.max(grid[0][0], grid[n - 1][n - 1]);
  let hi = n * n - 1;
  while (lo < hi) {
    const mid = (lo + hi) >> 1;
    if (canSwim(mid)) hi = mid;
    else lo = mid + 1;
  }
  return lo;
}
```

Time **O(n² log n²)** — binary search over at most `n²` levels, each BFS **O(n²)**. Space **O(n²)** for the visited grid per check. Dijkstra with a binary heap achieves **O(n² log n)** in one pass — worth mentioning if the interviewer prefers a single traversal.

## In an interview

Restate: square grid, start top-left, end bottom-right, uniform water rise, find earliest time you can arrive. Confirm 4-directional movement and that you may wait on dry land (does not change the minimax level).

Say monotonicity first — binary search the water level, check reachability — or Dijkstra where path cost is the maximum cell elevation along the route. Both are correct; pick the one you can code cleanly.

Expect: Union-Find variant (sort cells by elevation, merge neighbors — Kruskal-style), comparison to 03.24 Path With Minimum Effort (effort = max absolute height diff). Bug to name first: forgetting that start and end must both be `≤ t` — checking only interior cells.
