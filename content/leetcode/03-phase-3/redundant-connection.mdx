## One extra edge in a tree-plus-one

A connected undirected graph on `n` nodes has `n` edges — exactly **one cycle**. Edges arrive in order; return the **last** edge that can be removed so the graph stays a tree (still connected).

For `edges = [[1,2],[1,3],[2,3]]`, edges 1–2 and 1–3 build a tree on three nodes. Edge `[2,3]` connects nodes already in the same component — that is the redundant edge. Answer: `[2,3]`.

DFS cycle detection on the full graph works but revisits structure unnecessarily. Union-Find streaming edges is cleaner: the first time `union(a, b)` fails because `find(a) === find(b)`, that edge closes a cycle. Process edges in input order; the **last** failure is the answer.

## Online cycle detection with Union-Find

Initialize `n` singleton sets. For each `[u, v]` in order: if `find(u) === find(v)`, record this edge as redundant (keep updating — last one wins); else `union(u, v)`.

The invariant: after processing `k` edges without redundancy, the graph has at most one extra edge total; when the redundant edge appears, both endpoints already lie in one component.

<Steps>
<Step title="Initialize UF">
`parent[i] = i` for nodes `1..n` (LeetCode uses 1-indexed labels).
</Step>
<Step title="Process edges in order">
For `[u, v]`, if same root, set `answer = [u, v]`; else unite.
</Step>
<Step title="Return last redundant edge">
After the loop, `answer` is the last edge that would have formed a cycle.
</Step>
</Steps>

## Solution

```ts
function findRedundantConnection(edges: number[][]): number[] {
  const n = edges.length;
  const parent = Array.from({ length: n + 1 }, (_, i) => i);

  function find(x: number): number {
    if (parent[x] !== x) parent[x] = find(parent[x]);
    return parent[x];
  }

  let redundant: number[] = [];
  for (const [u, v] of edges) {
    const pu = find(u), pv = find(v);
    if (pu === pv) redundant = [u, v];
    else parent[pv] = pu;
  }
  return redundant;
}
```

Time **O(n × α(n))** ≈ **O(n)** for `n` edges. Space **O(n)**.

## In an interview

Restate: `n` nodes, `n` edges, connected, undirected, return last redundant edge in order. Draw the triangle example.

Say Union-Find before coding: if endpoints already connected, edge is redundant; keep the last such edge. Mention 1-indexed nodes.

Expect: Redundant Connection II (directed), "which edge to remove if multiple cycles?" (this problem has exactly one extra edge), MST connection (Kruskal skips redundant edges the same way). Bug to name first: returning the **first** redundant edge when the problem asks for the **last** — process all edges and overwrite.
